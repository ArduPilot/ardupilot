# RP2350 Scratch Y registry — SRAM9 (0x20081000, 4 KB), core1 dedicated I-CODE bus.
# Functions here get single-cycle instruction fetch on core1 with zero bus-fabric contention.
# Rule: core1-only hot paths (rate controller thread at 1 kHz + notch filter chain).
# Budget: 4096 B total.  Current usage: ~2048 B.
#
# IMPORTANT: functions listed here must NOT also appear in rp2350_ramfunc2_registry.txt.
# The linker claims .text sections first-come-first-served; duplicates would be silently dropped.
#
# Rate controller PID (core1, 1 kHz — called 3x per tick for roll/pitch/yaw):
#libraries/AC_PID/AC_PID.cpp|AC_PID::update_all
# Rate controller entry point (core1, 1 kHz):
#libraries/AC_AttitudeControl/AC_AttitudeControl_Multi.cpp|AC_AttitudeControl_Multi::rate_controller_run_dt
# NOTE: HarmonicNotchFilter::update is called from core0 (update_dynamic_notch_at_ in scheduler),
# and HarmonicNotchFilter::apply / NotchFilter::apply are called from AP_InertialSensor::update on
# core0 as well as the rate thread on core1.  Placing these in SRAM9 creates AHB bus contention
# (core0 accessing SRAM9 via bus fabric while core1 fetches from SRAM9 via dedicated I-CODE).
# Keep them in flash (XIP cache) where both cores benefit from the shared 16 KB I-cache.
#
