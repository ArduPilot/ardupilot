# Boot-order hazard for the libc helpers. The compiler lowers struct/array init
# in early boot into implicit calls to memcpy/memset and the 64-bit divide
# helpers, and those run before rp_clock_init() copies .ramtext to SRAM
# (rp_clocks.c). Relocating a helper that early boot calls executes
# uninitialised SRAM and the FC double-faults.
#
# memcpy and memset ARE relocated, but not from here - common_rp2350_smp.ld
# picks the newlib archive members directly, with a matching EXCLUDE_FILE on
# the flash .text sweep. That is the only mechanism that works for them:
# newlib has no per-function sections, and its libc.a is not under the build
# root that the symbol map is built from, so a symbol entry here matches
# nothing and only prints a warning. It is safe because the copy loop in
# rp_clocks.c was rewritten as a volatile word loop so it no longer calls
# them. See the memcpy/memset section of hwdef/Laurel/BASELINE.md before
# touching that, and do not add entries for them here - a duplicate pick is
# claimed first-come-first-served and silently drops one of the two.
#
# __udivmoddi4 and __aeabi_uldivmod are NOT relocated and must stay in flash -
# nothing has been done to keep them off the early-boot path. They profile hot
# on core1 (~4.4% of active time); claw that back by removing the calls (e.g.
# 32-bit micros() deltas) rather than by moving the symbol. They also live in
# libgcc, which has no per-function sections, so a symbol entry silently
# matches nothing - an (archive) entry would be needed, and would boot-fault.

# newlib single-precision trig, from a core0 PC-sampler run on RPI_UAVFC.
# The AHRS/EKF math on core0 keeps these in the XIP working set: atan2f 0.4%,
# kernel_cosf/kernel_sinf/sinf 0.2% each, atanf 0.1% of all core0 samples,
# ~1.3% together and all flash-resident. cosf is included for symmetry with
# sinf rather than on its own sample count.
# Unlike memcpy/memset these are not reachable from early boot, so there is no
# .ramtext copy-order hazard.
# Deliberately not relocated: __ieee754_rem_pio2f and __kernel_rem_pio2f are
# the large-argument reduction path and did not profile, and tanf is only
# reached when a filter cutoff actually changes.
# newlib is not built with -ffunction-sections, so these have to be picked as
# whole archive members rather than by symbol. Each member holds one function.
